# Prometheus 0.2.2

## Store-Facing Release Notes

0.2.2 is the first Store update since 0.1.7. It exposes 15 read-only MCP tools over the existing Prometheus API (PromQL instant and range queries, metric/label discovery, targets and service discovery, alerts, rules, and runtime/TSDB/flags/config status) with explicit access declarations, host-bound lifecycle identity and redacted output; manifest permissions remain empty and upgrading grants no access. It also corrects the author release metadata so DBX Store can import the release, and removes the unsupported mcpTools field. UI and service behavior are unchanged. A matching updated DBX Desktop and standalone MCP are required.

## Why A New Version

Neither 0.2.0 nor 0.2.1 entered the Store. Describing only the 0.2.1 metadata
repair omitted the 15-tool MCP bridge that users upgrading from Store 0.1.7 will
actually receive. The author release must use the Store-importable top-level
`plugin` identity plus `artifacts` envelope rather than a flat catalog candidate;
unsupported `mcpTools` listing metadata must remain absent. The unchanged MCP
contribution stays in `manifest.json`.

0.2.2 is a new immutable release for the maintainer-review response and clean CI
provenance. Preserve 0.2.0/0.2.1 tags, assets, notes and receipts; none establishes
0.2.2 verification. Source is pinned to
[`v0.2.2`](https://github.com/caichangqing1120/dbx-plugin-prometheus/tree/v0.2.2).

## Required CI And Provenance Gates

Use clean CI through the official reusable workflow pinned at
`417c1bfc28ea8669dfbc2e1525f54e3b68285b1c`. Its caller sets
`install-plugin-cli: false` to avoid rewriting the backend module and preserves
the existing `replace ... => ./sdk` relationship. Go 1.26.3 builds the sidecar
directly through the provenance-aware helper:

```sh
RELEASE_TAG=v0.2.2 DBX_PLUGIN_TARGET=<target> python3 scripts/package-ci.py
```

For each of the six supported targets, the helper emits
`dist/<id>-<version>-<target>.dbxp`, `.artifact.json` and `.provenance.json`.
Full VCS provenance verification is mandatory: inspect the packaged executable's
`go version -m` build information, require `vcs.revision` to equal the commit
resolved by `v0.2.2`, require `vcs.modified=false`, and retain the complete build
information and provenance record. Missing or mismatched provenance must fail
packaging, even if initialize reports 0.2.2. Check packaged identity/version,
target architecture and SHA256/size against emitted metadata and final release
inputs; import the unmodified author envelope through the actual Store importer
and validate its generated catalog candidate.

Fresh 0.2.2 CI execution, downloaded-byte/provenance verification, immutable author
publication and Store review/signing are pending delivery gates. These notes do
not claim any of those results. Historical or local packages cannot substitute
for clean CI output.

## Unchanged Safety And Acceptance Boundaries

All 15 exact read-only MCP declarations/access levels, plugin ID/publisher, empty
manifest permissions, UI and service API behavior remain unchanged. Installing or
upgrading grants no tool or connection access; explicit enablement/authorization
and matching updated DBX Desktop plus standalone MCP are still required. The
existing engine floor alone does not demonstrate the new protocol is supported.

No new Desktop installation, live Prometheus acceptance, production-service call
or official Store signing is established by the metadata/docs update. Local
fixture tests, cross-target builds and Store validation are separate evidence.
